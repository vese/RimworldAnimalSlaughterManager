# Расширение интеграциями

Механизм подключения контента других модов — небольшой DI в духе сервис-коллекции ASP.NET
(размера мода): интеграция регистрирует свой адаптер реализацией одного или нескольких
сервисных контрактов в `IntegrationServices`; ядро резолвит все реализации контракта
(`IntegrationServices.GetServices<T>()`) и никогда не знает конкретные типы. Регистрация — из
класса `[StaticConstructorOnStartup]` в папке самой интеграции (или сторонним модом).

## Сервисные контракты (по одному на файл в `Core/Integrations.Shared/`)

| Контракт | Точка потребления | Что даёт |
|---|---|---|
| `IRuleOptionsSource` | меню добавления правил приоритетов | свои опции, свои правила |
| `ISettingsTabSource` | окно настроек вида | своя вкладка |
| `IPawnSlaughterSignals` | сортировка корзин забоя | тай-брейкер сигналы (good/bad) животного |
| `IKeepReserveSource` | резервация племенного ядра | кого держать от забоя (в пороге), подсчёт, наличие правил |
| `IKindForceCullSource` | принудительный забой по правилам | кого забивать вопреки лимитам |
| `IExternalForceCullSource` | принудительный забой чужим модом | решения чужого мода (его UI), гейт прохода |
| `IKindIntegrationSettingsProvider` | настройки вида | свои данные в сейве/пресетах — своим ключом и XML-секцией |

Ядро суммирует/объединяет ответы всех реализаций (сигналы складываются, опции меню и выборки
делегируются всем, одиночные вопросы — «хоть одна»). Ничего не зарегистрировано — вызовы
безопасно возвращают пустоту, отдельных проверок у потребителей нет.

## Как делается интеграция

1. Отдельный проект `AnimalSlaughterManager.Integrations.<ModName>` (ссылается на Core) — всё
   интеграционное в нём: обёртка чужого API (Access-класс), адаптеры контрактов, свои
   модели/правила/UI, `README.md`. Главный проект добавляет его в ссылки и в сборку.
2. Адаптер реализует нужные контракты; всё интеграционно-специфичное (перечисление дефов,
   проверки на пешке, цвета/тултипы) вызывает напрямую из своей обёртки — в контракты входит
   только то, что нужно ядру.
3. Класс регистрации `[StaticConstructorOnStartup]`: при активном чужом моде —
   `IntegrationServices.Add<Контракт>(adapter)` для каждого контракта; провайдер настроек
   вида — безусловно (данные переживают выключение чужого мода).
4. Свои настройки вида: `IKindIntegrationSettings` (`WriteXml/ReadXml` — своя секция пресета)
   + `PresetSectionSerialization` (сериализация секций).

## Правила расположения

- контракты — `Core/Integrations.Shared/`, реестр — `Core/Integrations/`; реализации —
  только в своём проекте интеграции;
- описание конкретной интеграции — в её `README.md`, не в общей доке;
- общая спека механизма — `Specs/integrations.md`; специфика интеграции — в её папке.
