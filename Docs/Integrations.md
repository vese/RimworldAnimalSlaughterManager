# Расширение интеграциями

Механизм подключения контента других модов: точка расширения — реестр, использование — только
через контракты (передаются в ядро при регистрации,_dependency injection без прямых ссылок на
реализации). Интеграция саморегистрируется при старте из своей папки; зарегистрировать её может
и сторонний мод (public-реестр, `[StaticConstructorOnStartup]`).

## Что можно расширить

| Точка расширения | Контракт | Что даёт |
|---|---|---|
| Черты животных | `ITraitsIntegration` (список, агрегируется) | правила приоритетов с чертами, таблица-пикер, вкладка особых правил, keep/force-cull движка |
| Настройки вида | `IKindIntegrationSettings` + провайдер (список) | свои данные в настройках вида и в пресетах — своим ключом и своей XML-секцией |

Ядро потребляет `IntegrationRegistry.Traits` (агрегат всех зарегистрированных реализаций) и
`IntegrationRegistry.KindSettingsProviders`; несколько интеграций одного контракта
сосуществуют: множества объединяются, опции меню/выборки делегируются всем.

## Как делается интеграция

1. Папка `src/Integrations/<ModName>/` — всё интеграционное живёт в ней: обёртка чужого API
   (Access-класс), адаптер контракта, свои модели/правила/UI, `README.md` с описанием.
2. Адаптер реализует контракт(-ы); на каждый метод контракта — поведение по умолчанию
   («ничего нет»), чтобы ядро не проверяло наличие.
3. Класс регистрации `[StaticConstructorOnStartup]` в папке: при активном чужом моде —
   `RegisterTraits(...)`; провайдер настроек вида — `RegisterKindSettings(...)` безусловно
   (данные настроек переживают выключение чужого мода).
4. Свои настройки вида: `IKindIntegrationSettings` (`WriteXml/ReadXml` — своя секция пресета;
   легаси-плоские узлы читаются самим классом) + хелперы `PresetSectionXml`.

## Правила расположения

- контракты и реестр — `src/Integrations/`; реализации — только в своей папке;
- описание конкретной интеграции — в её `README.md`, не в общей доке;
- общая спека механизма — `Specs/integrations.md`; специфика интеграции — в её папке.
