# Спека: интеграции со сторонними модами

Контекст: ядро мода обращается к контенту сторонних модов только через реестр
(`IntegrationRegistry`), по контрактам (`ITraitsIntegration`); пока интеграция не
зарегистрирована, работает пустое поведение (NullObject). Механизм — `Docs/Integrations.md`.

Терминология:
- **Интеграция** — папка `src/Integrations/<Mod>/`: обёртка чужого API, адаптер контракта,
  свои модели/правила/UI.
- **Саморегистрация** — класс `[StaticConstructorOnStartup]` в папке самой интеграции
  (у ATS — `AnimalTraitsSystemRegistration`); ядро интеграции по имени не называет.
- **Пустое поведение** — `NoneTraitsIntegration`: ответы «ничего нет» без проверок у вызывающих.

## Сценарии

### Спека 1: чужой мод не активен — контента нет нигде

```gherkin
Rule: Нет интеграции
  Given мод ATS не активен в списке модов
  When игра загружается
  Then реестр отдаёт пустое поведение
  And в меню добавления правил нет опций про черты
  And в окне настроек вида нет вкладки «Особые правила»
  And движок забоя не находит ни одной черты и не делает ATS force-cull
```

### Спека 2: чужой мод активен — услуги зарегистрированы

```gherkin
Rule: Регистрация при старте
  Given мод ATS активен
  When игра загружается
  Then интеграция саморегистрируется в реестре ([StaticConstructorOnStartup] в своей папке)
  And в меню добавления правил появляются опции черт
  And в окне настроек вида появляется вкладка «Особые правила» (между
    «Приоритетами» и «Общими»)
  And движок забоя видит черты и ATS force-cull
```

### Спека 3: пустое поведение не требует проверок у вызывающих

```gherkin
Rule: NullObject
  Given реестр отдаёт пустое поведение
  When любая часть ядра вызывает любую услугу контракта
  Then ответ безопасен и без содержания (нет черт, нет забоя, нет вкладки,
    меню без опций) без отдельного условия «активен ли чужой мод»
```

### Спека 4: правила приоритетов черт попадают в общую валидацию

```gherkin
Rule: Валидация контракта
  Given список правил приоритетов содержит правила интеграции (черта / тип черты)
  When проходит валидация списков (см. validation-rules.md)
  Then правила проверяются теми же валидаторами, что и ванильные
  And сет оси черт (AnimalTraitSet) принадлежит интеграции, но участвует в общем
    проходе закрытия через TraitSetTypes правила
```

### Спека 5: добавление новой интеграции не трогает ядро

```gherkin
Rule: Точка расширения
  Given появляется второй мод-источник контента
  When для него создаётся папка интеграции с контрактом/адаптером
  Then ядро не меняется вовсе: интеграция саморегистрируется классом
    [StaticConstructorOnStartup] внутри своей папки
  And вне папки интеграции не появляется ссылок на обёртки чужого API
```

## Инварианты

- Вне `src/Integrations/` нет ссылок на обёртки/типы конкретных чужих модов; ядро знает
  только контракты реестра.
- Ядро не называет интеграции по имени: регистрация живёт в самой интеграции
  ([StaticConstructorOnStartup] в её папке), ядро знает только реестр и контракты.
- Пустое поведение покрывает каждую услугу контракта: «нет контента», «нет UI», «нет забоя».
- Изменение набора услуг контракта меняет и пустое поведение (оно всегда определено).
