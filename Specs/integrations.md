# Спека: механизм интеграций

Контекст: контент сторонних модов подключается через сервисный реестр (`IntegrationRegistry`,
DI-подобный): ядро резолвит реализации контрактов (`Services<T>()`), интеграции регистрируют
адаптеры при старте из своих папок — или сторонним модом. Ничего не зарегистрировано — вызовы
возвращают пустоту (NullObject-семантика).

Терминология:
- **Интеграция** — папка `src/Integrations/<Mod>/`: обёртка чужого API, адаптер контрактов,
  свои модели/правила/UI, README.
- **Саморегистрация** — класс `[StaticConstructorOnStartup]` в папке интеграции.
- **Сервисный контракт** — интерфейс из `src/Integrations/`, по одному на точку потребления
  (опции меню правил, вкладка настроек, сигналы сортировки, резервация, force-cull, настройки
  вида).

## Сценарии

### Спека 1: ничего не зарегистрировано — контента нет нигде

```gherkin
Rule: Нет интеграций
  Given ни один сервис не зарегистрирован
  When игра работает
  Then Services<T>() возвращает пустые списки
  And в меню добавления правил нет чужих опций
  And в окне настроек вида нет чужих вкладок
  And движок забоя не находит чужого контента
```

### Спека 2: регистрация при старте

```gherkin
Rule: Регистрация
  Given чужой мод активен
  When игра загружается
  Then адаптер интеграции регистрируется под свои контракты (Add<T>)
  And чужие опции/вкладки/контент появляются
```

### Спека 3: пустота не требует проверок у вызывающих

```gherkin
Rule: NullObject
  Given ни один сервис не зарегистрирован
  When любая часть ядра резолвит и вызывает контракт
  Then ответ безопасен и без содержания без отдельного условия «зарегистрировано ли»
```

### Спека 4: несколько реализаций одного контракта сосуществуют

```gherkin
Rule: Композиция
  Given под контракт зарегистрированы две реализации
  When ядро резолвит контракт
  Then обе участвуют: суммы складываются (сигналы), списки объединяются (опции, выборки),
    одиночные вопросы истинны, если хоть одна реализация отвечает истинно
```

### Спека 5: настройки вида переживают выключение чужого мода

```gherkin
Rule: Хранение настроек
  Given в настройках вида есть данные интеграции
  When чужой мод выключен и сейв загружен
  Then провайдер настроек зарегистрирован (безусловно) и данные читаются/сохраняются
  And применяются при повторном включении
```

### Спека 6: новая интеграция не меняет ядро

```gherkin
Rule: Точка расширения
  Given появляется новый источник контента, укладывающийся в существующие контракты
  When для него создаётся папка интеграции с адаптером и классом саморегистрации
  Then ядро не меняется вовсе
```

## Инварианты

- Реестр — единственная точка расширения; ядро использует только контракты.
- Контракт — по точке потребления ядра: интеграционно-специфичные запросы (перечисление
  дефов, проверки черты) в контракты не входят — они остаются внутри папки интеграции.
- Хранение данных интеграции: в настройках вида — по ключу провайдера; в пресетах — своя
  XML-секция (легаси-форматы читаются самой интеграцией).
