# Спека: валидация списков правил приоритетов забоя

Контекст: список правил обрабатывается сверху вниз; побеждает первое совпавшее правило;
не совпавшее ни с чем животное сортируется по возрасту из настроек. Проверка — по
аккумулированным данным сетов (событийная модель закрытия), без обращения к живым животным.

Терминология:
- **Сет (TraitSet)** — одна ось животного (беременность, привязанность, болезни,
  тренировка, черты). Правило относится к одному или нескольким сетам
  (`TraitSetTypes`); в рамках сета проверяются все правила этого сета.
- **Ось def'а** — для каждого упомянутого правилами def'а (болезнь, навык, черта) два
  состояния: «есть» и «нет». Хранится словарём def → закрытые состояния.
- **Агрегатная ось** — состояние, производное от всех def'ов сета сразу: «здоров /
  болен любым» (болезни), статусы тренировки (не/частично/полностью), «есть любая /
  положительная / отрицательная / foreign-черта», «беременна / не беременна».
- **Закрыть состояние** — правило в порядке списка закрывает состояния осей
  (def-флаг или агрегатную ось), запоминая свой индекс.
- **Избыточное правило** — все состояния осей, которые оно матчит, уже закрыты
  предыдущими правилами сета.
- **Исчерпывающее правило** — закрывает последнее открытое состояние осей сета.

Комбинации def'ов (подмножества 2ⁿ) не перебираются: правило по конкретному def'у
зависит только от него, поэтому покрытие факторизуется по осям. Состояние «все def
присутствуют одновременно» не проверяется — набор def'ов открыт, мод может добавить
новый def или убрать существующий.

## Сценарии

### Спека 1: дубликаты

```gherkin
Rule: Дубликат
  Given два правила одного типа с идентичной мишенью и параметрами
  When проходит валидация
  Then оба правила помечены «Дубликат правила N»
```

Примеры: две «Беременная» (has=true); два «Болен гриппом»; два TraitGeneral с одинаковыми type+inheritability.

### Спека 2: покрытие одного типа (порядок)

```gherkin
Rule: Покрытие
  Given правило A выше правила B, и множество животных B ⊆ множество A
  When проходит валидация
  Then B помечено «Избыточное правило: ... правилами N» (N = A)
```

Примеры:
- TrainingGeneral(Част.илиПолн.) выше TrainingGeneral(Полностью).
- TrainingGeneral(Полностью) выше Training(t, выучен) — при общем сете Training.
- Trait(черта X, any inheritability) выше Trait(X, наследуемая).

### Спека 3: покрытие разных типов в одном сете

```gherkin
Rule: Межтиповое покрытие
  Given правило A и правило B относятся к одному сету, но к разным типам,
    и A (выше) покрывает B
  When проходит валидация
  Then B помечено избыточным
```

Примеры: DiseaseAny(болен) выше Disease(болен гриппом); TraitGeneral(положительная, есть)
выше Trait(конкретная положительная черта).

### Спека 4: событийное закрытие внутри сета

```gherkin
Rule: Закрытие осей
  Given правила сета обрабатываются в порядке списка
  When правило закрывает состояния осей сета (def-флаг или агрегатную ось)
  Then закрытые состояния запоминают индекс закрывшего правила
  And последующие правила сета не переоткрывают их
```

### Спека 5: избыточность по закрытым осям

```gherkin
Rule: Избыточность в сете
  Given все состояния осей, матчащие правило R, уже закрыты предыдущими правилами сета
  When проходит валидация
  Then R помечено «Избыточное правило: подходящие животные уже отобраны правилами N,M»
```

Пример: TrainingGeneral(Частично) после TrainingGeneral(Част.илиПолн.) — статус Partial
уже закрыт.

### Спека 6: исчерпание сета — помечается закрывающее правило

```gherkin
Rule: Исчерпание
  Given правило R закрывает последнее открытое состояние осей своего сета
  When проходит валидация
  Then R (не правила ниже!) помечено «Это правило закрывает последнюю комбинацию —
    все правила ниже никогда не сработают»
  And правила ниже НЕ помечаются из-за R
```

Пример: [Не тренирован, Частично, Полностью, Беременная] — помечается правило 3
(«Полностью»), правило 4 не помечается. Тройка без правил ниже — правило 3 всё равно
помечено: предупреждение, что любое новое правило ниже не сработает.

Обоснование: закрыть все точки одного сета = закрыть всех животных (любое животное
имеет какое-то состояние каждой оси). Виновник — последнее закрывающее правило; игроку
проще исправить его, чем каждую жертву.

### Спека 7: независимость сетов в проверках

```gherkin
Rule: Пер-сетовость
  Given правило R сета S1 и правило Q сета S2 (не пересекаются сетами)
  When проходит валидация
  Then закрытия Q не влияют на избыточность R и наоборот
  And межсетовая избыточность не проверяется
```

Пример: [Не тренирован, Частично, Полностью] — правила сетов беременности/привязанности
не участвуют в проверке тройки.

## Инварианты

- Валидация не вызывает `Matches(Pawn)` — только накопленные данные сетов.
- Результат валидации кэшируется: пересчёт — только после изменения правил через
  методы настроек (`PriorityRuleSet`/`KindPrioritySettings`); Alert и отрисовка вкладки
  получают кэш.
- Пространство состояний не перебирается по подмножествам def'ов: закрытие считается
  по осям (def-флаги + агрегатные оси), O(n) по числу упомянутых def'ов.
- Одновременное присутствие всех def'ов не считается различимым состоянием —
  def-набор открыт (моды добавляют и убирают def'ы).
- Сообщения содержат номера правил (1-based) для навигации.
- Правило без сетов (`TraitSetTypes` пуст) не участвует в закрытии и всегда валидно.
